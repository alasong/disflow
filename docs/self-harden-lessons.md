## 1 本轮**宿主自己**犯的调用与判据错误（按要求单列）

前四条是本轮点名要求的；后七条是同一轮里我复查出来的。**每条都写「怎么发现的」**，
因为「错了没关系，没发现才是问题」。

| # | 犯了什么 | 原始读数 / 怎么发现的 | 下次怎么避免 |
| --- | --- | --- | --- |
| H1 | 合并 worktree 分支时**漏 `origin/` 前缀**（凭记忆写 ref） | 分支真实名是 `disflow/<tree>/<node>`（`disflow/worktree.py` 的 `branch_for`），`git branch -a` 可查；报错发生在合并那一刻 | 合并前先 `git branch -a` 对一下**完整** ref，别用缩写/记忆；`git merge` 的 ref 要与 `worktree list` 的输出对账 |

## 2 三类「声明 vs 现实」裂缝（本轮反复出现的模式）

### 2.1 同一批产物**互相把对方写旧**（本轮至少 3 例）

这不是措辞问题，是本轮最贵的教训：**在新节点落地之后，旧节点写下的「事实」会静默过期。**

| 例 | 谁写旧的 | 读数 |
| --- | --- | --- |
| README 的测试数 `563 != 567` | n10 与 n16 各量了一次总数，n16 的 4 个测试先合进 main | 被 n10 新加的守卫**当场**跑红；`fce1287` 修 |
| `.agents/skills/disflow/SKILL.md` §3 第 4 条的机制解释 | n5 写「提交了门就看不见」，n6 紧接着把门修成**看得见**（`start` 一律记 `head_sha`） | n12 评估记为 **U2**；本轮（n13）改写 §3 并加守卫 |
| n3 的 `goal` | 需求写「属于**故障**」，实现的取证裁决改成「**需人判断**」 | n12 评估记为 **U1** |

**前向修法（本轮定下的做法）**：写「事实」时**连判据命令一起写**。没有判据的事实，下一轮
既不知道它还成不成立，也不知道该重跑什么。SKILL 新增的 §10 就是按这个形状写的。

### 2.2 提问通道：契约写的是 A，worker 实际走的是 B

`brief` 的 `question_policy.how` 教 worker「把问题写进 `collect --result` 的 `summary`、`status`
置 `blocked`」。**实测它基本没被走**：

```text
node.collect 里 status=blocked 的条数 = 0        （全部 11 条 node.collect 都是 ok）
同期 pi 的 99 个 worker 会话里 contact_supervisor 被调 = 27 次
```

⇒ worker 的问题**不进 disflow 的事件流**：`disflow board` / `state.json` / `metrics` 都看不见。
「宿主读到 `blocked` 再决定」这条契约，实际要**宿主自己把问答补记**，否则这棵树对后人就是
「从没问过」。`collect` 仍是**结果**的落盘通道（别省），但它不是**提问**的通道。

### 2.3 承诺 vs 覆盖：注释说「同样要防漂移」，代码没接上

`tests/test_docs.py` 在 `SKILL` 定义旁写着宿主手册「同样要防漂移」，但**动词防漂移**那两条
断言的输入 `DOC_FILES` 只含 `README.md` 与 `docs/*.md`——**SKILL 不在其中**。实测：
`_verbs_in(SKILL)` 能认出 `clone` 这种并不存在的动词，却不会被任何断言拦下。

本轮**只观察、不修**（不扩大改动面）：这条记在这里，谁下一轮要动就顺手把它接上
（`DOC_FILES` 加上 SKILL 即可，代码里那句注释本来就写着这个意图）。

## 3 效率：代价读数 ↔ 四条纪律

代价是从本仓 **46 个子会话**的 `session.jsonl` 机械数出来的（不是感觉）。

| 纪律 | 代价读数 | 为什么 |
| --- | --- | --- |
| 负向对照只跑**目标测试文件**（`-p test_x.py`，0.2–2s）；**全量只在收尾跑一次** | 全量被跑 **92** 次 × 46–65s ≈ **76 分钟**纯等；最差一条 lane 181 消息 / 84 次 `bash`，为 5 条对照跑了 **24** 次变异 | 全量 46–65s、目标文件 0.2–2s，差两个数量级 |
| 禁 `sleep` 轮询：<90s 前台跑；>90s 放后台，去做别的事，**≤3 次** `tail` 查结果 | `sleep N` 累计 **1236 秒 ≈ 20 分钟**前台空等 | 空转不产生任何读数 |
| 先 `grep -n`（或查索引）再读，**别整读文件找符号** | 实测 `read : grep = **407 : 50**` ≈ **8:1**（整读主导） | 整读是 O(文件) 换一次 O(命中) |
| 别为「确认」**反复跑同一条命令**（幂等查询如 `git status` / `ls` 除外） | 见上两条的超额次数 | 同输入同输出，再跑一次只花时间 |

**根因不在 worker，在派活模板**：v1 模板要求「每条对照都要负向对照」却**不限定范围**，也掉了
「开工先交计划」这一条。v2 生效后，同一节点续跑的形状是：全量**一次**（55.7s）· 无 `sleep` ·
负向对照只跑目标文件（~4s）。
