### ~~C5. 租约按**机器速度**建模，人速干活会“假红”~~ ✅ 已修（本轮）

场景：人（不是 agent）在一个节点上干了超过 `lease_ttl`（默认 **900s = 15 分钟**）。

**修前的实测**（拿证据说话）：

| 步骤 | 旧行为 |
| --- | --- |
| `start` 后过了租约期 | `doctor` 报「租约超时未回收（可 `disflow reap`）」，**退出码 1** |
| 照它建议 `reap` | 节点 `running` → **`pending`**（而人还在干） |
| 人已干完活，直接 `done` | ✅ 仍成功（工作不丢）—— 但这一点当时**没写进任何文档**，属意外行为 |

**病因归类**：这是**「两种病因共用一个信号」**——同一类错在本轮已修过一次
（变异 harness 把「针脚未应用」与「真漏抓」混进同一个 `bad` 桶）。
标准修法也一样：**按病因拆开**。但 `doctor` 确实**无法**区分两者，
所以不能假装能——改报**事实 + 两种读法各自的正确做法**。

**已做**：

1. `ready.lease_overdue_seconds()` 给出**过期多久**（人能据此判断：几分钟 ≈ 还在干，几天 ≈ 崩了）。
   只有布尔值的报错把两种完全不同的情况说成同一件事。
2. `doctor` 新增**「需人判断」**一节：不计入退出码，状态为全绿；
   报 `已过期 <时长>（holder=<谁>）` + 两种读法与各自正确做法；
   并明说**为什么 `done` 不要求租约**（租约防并发，不防“收工晚了”）。
3. 「`done` 不要求租约」从意外行为升为**有意契约**：`design.md` §3.1 + 测试
   `test_done_does_not_require_a_lease` 钉住。

**为何没有把它变绿就完**：`is_stuck` 只看 **pending**，所以“worker 崩了留下 `running` 的节点”
会让树**静默停住**，而 `drive` 什么都不说——**`doctor` 是唯一说出它的地方**。
所以不能删，只能说准。

**仍未做（无当下受害者）**：按 `holder` 区分人/机（人干活不用租约）。
做到那个需要先解决“怎么知道 holder 是人还是机”——今天没有任何输入源声张这件事。

## D. 无需求支撑的扩展（按需再议）

| # | 是什么 | 触发条件 | 完成判据 | 备注 |
| --- | --- | --- | --- | --- |
| D1 | **每树物理隔离**（`DISFLOW_STATE_DIR/<tree>/events.jsonl`） | 单树事件量大到需要独立备份/权限 | 跨树查询（`trees`/`awaits`/`closed`）仍可用 | ⚠️ 现在**多树共享一条事件流是有意的**——`closed` 与 `awaits` 需要全局视图。改分区要重写 `closed` 读取路径，**不是纯搬家** |

| D3 | **Windows 跨进程加锁**（`msvcrt.locking` 或锁文件轮询） | 真有人在 Windows 上跑写操作 | 非 POSIX 平台上 `start`/`done` 等写动词可用 | 今天 `fcntl` 已惰性导入 ⇒ 非 POSIX 上 `import disflow` 与**读操作可用**，只在写时报一句能看懂的错（不再是一整包不可导入）。**不静默降级为不加锁**：那会变成并发写没保护 |

## E. 明确不做（防止反复讨论）

| 项 | 理由 |
| --- | --- |
| 常驻 daemon / `spawn` | FR-16 非目标：分发器**只推不跑**；保活只在进程池层 |
| LLM 参与确定性判定（就绪/依赖/波次） | 非目标：确定性逻辑不给 LLM 生成 |
| 多机分布式调度 | 非目标（本期） |
| 替代 Airflow / Temporal 的通用性 | 非目标 |
| `phase → stage`（C2） | mgt 的 phase 是**排期批次**，disflow 的 stage 是**流程位置**；强映射造出假语义 |
| 把 `done` 当业务词针脚 | 它既是机制终态（`core.TERMINAL`）又是视图列取值，**不可判定**，已登记在 `design.md` §9.1 |
