| # | 是什么 | 触发条件 | 完成判据 | 备注 |
| --- | --- | --- | --- | --- |
| D1 | **每树物理隔离**（`DISFLOW_STATE_DIR/<tree>/events.jsonl`） | 单树事件量大到需要独立备份/权限 | 跨树查询（`trees`/`awaits`/`closed`）仍可用 | ⚠️ 现在**多树共享一条事件流是有意的**——`closed` 与 `awaits` 需要全局视图。改分区要重写 `closed` 读取路径，**不是纯搬家** |

## E. 明确不做（防止反复讨论）

| 项 | 理由 |
| --- | --- |
| 常驻 daemon / `spawn` | FR-16 非目标：分发器**只推不跑**；保活只在进程池层 |
| LLM 参与确定性判定（就绪/依赖/波次） | 非目标：确定性逻辑不给 LLM 生成 |
| 多机分布式调度 | 非目标（本期） |
| 替代 Airflow / Temporal 的通用性 | 非目标 |
| `phase → stage`（C2） | mgt 的 phase 是**排期批次**，disflow 的 stage 是**流程位置**；强映射造出假语义 |
| 把 `done` 当业务词针脚 | 它既是机制终态（`core.TERMINAL`）又是视图列取值，**不可判定**，已登记在 `design.md` §9.1 |

## F. 收口条件

v0.1 交付完成 = **PM1 批准**（唯一未决项）：

```bash
python3 -m disflow.cli start disflow-v0.1 PM1 --holder <你>
python3 -m disflow.cli done  disflow-v0.1 PM1 --decl '{"approver":"<你>"}'
```

即「批准」这个动作**有据可查**，但**按不按是人决定的**。

本文件不设优先级、不设 deadline。**没有触发条件就不动。**
