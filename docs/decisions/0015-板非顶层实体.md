# 0015 板不是顶层实体：降级 ADR 0005 的**结构层**（保留策略层）

- **Status**：Active
- **Date**：2026-10-13
- **Supersedes（部分）**：[0005](0005-看板提升为一等实体.md) 的**结构层**结论（「看板是一等实体：
  稳定 `id` 结构 + 板自身持有列结构 + 树降为板内维度」）。**保留** 0005 的**策略层**结论：
  分发策略（WIP）与逐列默认验收挂在板上（FR-30/31）。
- **判据来源**：`jev choice` conf **1.00**（A=1.00，unanimous）
- **关联**：[0003](0003-运行视图-v10-按板列不按树.md)（看板 = 阶段列）、
  [0014](0014-本质与未来形态.md)（可机检判据：是否产生第二份实现）、
  `docs/v0.2-backlog.md` §D6（本决定关闭它的触发条件）

## Context

用户提问（2026-10-13）：「**多个看板这条路基本上可以扔掉了？当前系统需要做哪些调整？**」

这问题戳中一个**长期存在但没人明说的落差**：ADR 0005 宣布「看板是一等实体」，但**结构层从未落地**。
实测（本轮命令读数，非印象）：

| 事实 | 依据 |
| --- | --- |
| `board_layout` **第一参数仍是树** | `disflow/views.py:151 def board_layout(tree: dict, ...)` |
| 板仍**寄生**在树下 | `disflow/engine.py:332 boards_from_projection(tree_state.get("boards"))` |
| `state.json` 顶层只有 `trees`/`specs` | `docs/v0.2-backlog.md` §D6（「实测现状 2026-10-12」） |
| backlog 自己承认 | §D6：「ADR 0005 **只做了策略层，结构层没落地**」 |

同时，板**实际承载 4 件事**，其中 3 件有真实机制咬合（拆掉 = 机制失去宿主）：

| 板做的事 | 源码落点 | 性质 |
| --- | --- | --- |
| stage 取值的**闭集**（写时校验列名合法） | `engine.py:336 _tree_stages` → `_validate_stage` | **机制** |
| **WIP 逐列并发上限** | `dispatch.py:113 wip_by_stage` | **机制**（FR-30） |
| **逐列默认验收** | `engine.py:355 _effective_acceptance` | **机制**（FR-31） |
| 列顺序 / 空列渲染 | `views.py:151` | 纯渲染 |

旁证：`boards.py:203` —— 板定义为空数组时**响亮拒收**（「没有板就没有看板」）⇒ 板是 `stage` 的
**值域定义**，不是可选装饰。

**改动面读数**（`lowest-cost` 要求的那一项）：坐实 D6 需动 `board_layout` 签名 ⇒
13 个模块含板/stage 消费点（views 89 / engine 84 / cli 58 / boards 56 / web 30 处），
5 个测试文件（`test_board_policy` / `test_boards*` / `test_stage_change`），
**一轮独立 PDCA**；而**用户可见行为影响为零**（`board` 输出不变、`ready` 不变、门不变）。

## Decision

**降级 ADR 0005 的结构层：板不是顶层实体。** 明确三条：

1. **板 = 树的一个字段**（`tree.stages` 语义），**不**升为 `state["boards"]` 顶层实体；
   `board_layout(tree, ...)` **保持**以树为第一参数。**不**做 D6。
2. **策略层保留**：WIP（FR-30）与逐列默认验收（FR-31）**仍在"列"上**——这里的"列"是
   `tree.boards` 里的列定义，与本决定不冲突（策略挂在列上不需要列是顶层实体）。
3. **"多块板" = 多棵树**（FR-22 不变）；跨树依赖仍是 `awaits` 显式信号（FR-23 不变）。

**判据（可机检，沿用 0014 第 2 节的降级版形式）**：

> 某物是否该升为独立实体，看**「不做它，是否有人能写出第二份实现」**。
> `views.py:10` 明写「布局**只有 `board_layout` 一处实现**」——**现在不能**。
> ⇒ 判据指向「**不做**独立实体」。

**代价读数对照**（决定就建立在这上面）：

| 路径 | 代价 | 用户可见收益 |
| --- | --- | --- |
| 坐实 D6（板升为顶层） | 改签名 → 3 处消费方 + 一轮 PDCA | **零** |
| 降级（本决定） | 改文档口径 + 一条 banner | **零** |
| 彻底砍掉 stage 概念 | 300+ 处 + 5 测试文件 + FR-30/31 重立 | 负（WIP/验收失去宿主） |

**零收益 + 高代价 = 不做**（`playbooks/lowest-cost.md`）。

## Consequences

- **需求基线不变**：FR-21/22/23 的机检标记**不需要改**——它们断言的是「板随事件流持久化、
  多树隔离、awaits 信号」（均已 ✅，且与"顶层实体"无关）。FR-21「固定列结构」的**结构层**
  部分按本决定解释为「列结构由 `tree.boards` 固定」，不要求顶层 `state["boards"]`。
- **`docs/design.md` §6 的 banner 需改写**：现有 banner 写「定位已升级（ADR 0005）：看板是
  **一等实体**」——与本决定冲突，改为「阶段列挂在树上；策略挂在列上（0005 策略层有效，
  结构层已由 0015 降级）」。
- **`docs/v0.2-backlog.md` §D6 关闭**：触发条件「有人真按『看板是主体、树是它的组织维度』工作，
  或需要跨树复用同一块板」**未出现**，且本轮判定**不做**。D6 保持关闭，但**不删除记录**
  （历史依据，且注明由 0015 关闭）。
- **代码零改动**：本决定纯文档口径——因为实机本来就是寄生形态，**降级是把文档改成与实机一致**，
  不是改实机。
- **不做**：`board_layout(board_id, ...)` 签名改造、`state["boards"]` 顶层化、
  「跨树复用同一块板」能力。
- **已验**：`views.py:151` / `engine.py:332` / `engine.py:336` / `engine.py:355` /
  `dispatch.py:113` / `boards.py:203` 六处行号均为本轮 `grep` 实测，非引用转抄。
