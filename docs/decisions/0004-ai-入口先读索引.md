# 0004 AI 入口：先读索引，再读源码

- **Status**：Active
- **Date**：2026-10-11
- **Supersedes**：—

## Context

一次**真实故障**（不是假想）：被问「disflow 的看板数据结构 / 处理流程是什么」时，AI 助手
直接 `ls` → `grep` → 整读 `disflow/*.py` 与部分 `docs/`，**全程没有打开 `assets/INDEX.md`
或 `docs/INDEX.md`**；直到用户追问「有读资产清单么」才暴露。

根因（三层，逐层更本质）：

1. **直接原因**：检索从源码起手，没先问「本仓有没有发布入口索引」。
2. **机制原因**：索引存在，但**没有任何常驻文件指向它** —— 仓里没有项目级 `AGENTS.md`，
   而 `docs/INDEX.md` 的「找文档先看这里」只有**打开 docs 之后**才看得见。即
   **入口指针自己没有一个入口**（who indexes the index）。
3. **纪律原因**：全局规则里有「答『以前/上次』先查记忆库 / 知识库」，但那管**跨会话记忆**，
   不管**仓内定位**；缺一条「仓内动手之前，先转向仓自己的索引」。

这与本仓自己的口号构成同一个笑话：资产登记的存在理由是「让 AI **不必整读代码**就能定位」
（`assets/README.md`），纪律是「**不登记 = 永不被读到**」（`docs/INDEX.md`）—— 而**索引本身**
没被任何常驻文件「登记」。

## Decision

1. 仓根新增 **`AGENTS.md`**（pi 每个请求常驻加载），其 §0 即
   「动手 / 回答前先读 `docs/INDEX.md` + `assets/INDEX.md`」，并写明 `stale` 的含义与
   新增登记的规矩。
2. `AGENTS.md` 本身**登记为资产**（`assets/registry.json` → `agents`），遵守「索引里的东西
   自己也在索引里」。
3. 加守卫 **`tests/test_agent_entry.py`**：常驻入口文件必须存在、必须指向两份索引、
   且指针路径必须真实存在。

## Consequences

- 「入口指针必须自身有入口」成为**机检项**：删掉 `AGENTS.md`、把指针从常驻文件里移走、
  或改坏索引路径 → 测试红。
- **边界（如实登记，不假装机检能覆盖行为）**：测试只能保证**指针存在且有效**，
  不能保证 AI 真去读它。后者靠本文件常驻（加载即见）+ 纪律补，属行为层，测试够不着。
- 判据命令：`python3 -m unittest tests.test_agent_entry`（在仓根、`-t tests` 前提下）。
