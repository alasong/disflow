# 0012 防漂移三门：goal_align / code_quality / verify_real（硬门 + 逃生口）

- **Status**：Active
- **Date**：2026-10-11
- **关联**：[0010](0010-kaa融合-声明式.md) 定的形态 2（互补判据落进既有扩展点）；
  本篇是它的**第二批落地**，也是用户诉求「避免被 ai 漂移影响太大」的直接兑现。

## Context

用户诉求（2026-10-11）：「**然后就是执行的质量，避免被 ai 漂移影响太大。**」

盘点当时的防线（源码实测）：

| 已有门 | 拦什么 | 性质 |
| --- | --- | --- |
| `scope_check` | 改了 `touch_plan` 外的文件 | 硬拒收 |
| `acceptance` | 产出不对 | 硬拒收 |
| `tree_coverage` | 分解了却没登记需求 | 硬拒收 |
| `tree_closure` | 没收尾（缺 evaluate/reflect） | 硬拒收 |
| `weak_reason` | 破例理由敷衍 | 硬拒收 |
| `claim_mismatch` | 声称测试通过而命令不是测试 | **仅信号**（进 evidence，不拒收） |

**缺口**：漂移最典型的三种形态，**一种都拦不住**：

1. **跑题** —— 验收命令写 `true` + 改动落在 `touch_plan` 内 ⇒ 两道门全绿，但内容跟目标无关。
2. **假证据** —— 声称「测试通过」而命令是 `true` ⇒ 只记信号；而本仓实测**信号没人看**。
3. **改坏产物** —— 语法错、宽捕获吞异常、可变默认参数、`shell=True`；验收命令常是
   「文件包含 X」这类弱判据，恰好不看这些地方 ⇒ 门全绿。

## Decision

**三道门全补，且都是硬门**（jev `choice` conf **0.95**，分布 0.96/0.01/0.02/0.01）。

| 门 | 判据 | 逃生口 |
| --- | --- | --- |
| `goal_align` | `goal` 与产出声明（summary）的**内容词交集为空** ⇒ 跑题。中文按 2-gram、英文按词，过停用词表 | `declarations.goal_waiver` |
| `code_quality` | 改动集里的 `.py`：① `ast.parse` 成功 ② 无裸/宽 `except` 且不重抛 ③ 无可变默认参数 ④ 无 `shell=True` | `declarations.code_waiver` |
| `verify_real` | 与 `claim_mismatch` **共用词表**的硬门版：声称测试通过而命令不含测试词 | `declarations.claim_waiver` |

**为何取硬门而非信号**（这是本篇最关键的判断）：

- 漂移**不会在证据里留下异常痕迹** —— 「做完了但没用」与「做完了且有用」在 evidence 上长得一样。
  信号模式要求人去翻 evidence，而本仓已实测**信号没人看**（`claim_mismatch` 上线后无人消费）。
- kaa 的经验佐证：它的 `verify_real` 是**混合门**，且 kaa 后来把门级一刀切改成**逐码风险分档** ——
  说明这类门的真风险是**误拒**，不是漏判 ⇒ 对策是**给逃生口 + 管住逃生口质量**，不是降级成信号。

**逃生口设计（三条，统一纪律）**：

- 每个 waiver 的理由**过 `weak_reason` 质量门**（写「无」「不需要」⇒ 拒收）——
  与 `no_result` / `scope_waiver` / `size_waiver` **同一套**，不做第二份。
- 破例**记入证据**（`evidence.goal_waiver` 等），可审计，不静默放行。
- **信息不足 ≠ 跑题**：任一侧切不出内容词（如目标叫 `A1`、`做 A`）⇒ **放行**，不拒收。

## Consequences

**已落地**：

- `disflow/gates.py`：`_goal_tokens` / `goal_align` / `_py_file_issues` / `code_quality` / `verify_real`。
- `disflow/vocab.py`：`GOAL_STOPWORDS` / `CODE_QUALITY_SUFFIXES` / `VERIFY_HINT_WORDS`。
- `disflow/config.py`：三个可配键 `goal_stopwords` / `code_quality_suffixes`（空 = 关掉该判据）。
- `disflow/engine.py` `done()`：三处接线 + 三个 waiver 的质量门。
- `tests/test_reason_quality.py`：**26 项**（含三道门的正反两向）。

**实测抓到的三个真缺陷**（记录，因为「门抓到了什么」比「门有多少」重要）：

1. **可变默认参数重复报 24 次** —— 把函数级检查嵌在 `ast.walk(tree)` 循环里，每个函数被外层
   每个 AST 节点各扫一遍。已拆成独立遍历。
2. **文件不存在时 `checked=True`** —— 假装验过（违反 `vacuous_reasons` 同款纪律）。已改成 `False`。
3. **`goal_align` 误伤 10 个既有测试** —— 短目标（`A1`）经停用词过滤后词集为空 ⇒ 交集必空 ⇒
   **逐字相同的目标与声称也被判跑题**。已修：任一侧词集为空 ⇒ 放行。
   另修：2-gram 也要过停用词（否则「做一个需求分析」与「做一个日志清理」共享碎片「做一」）。

**已知限制（诚实标注）**：

- `goal_align` 判的是**相关性**，不是**正确性** —— 「与目标有共同词但做错了」照样通过。
  它是**跑题探测器**，不是质量判据。
- `code_quality` 只查四条**正确性**底线，不查风格（风格门会诱发大量无意义摩擦）。
  只覆盖 `.py`（其他语言的底线判据未做）。
- 三道门都可能对**特殊合法形态**误拒（如纯重构节点与目标词不重叠）—— 逃生口是为此准备的，
  且理由必须具体。**误拒的代价是补一个 waiver，漏判的代价是假绿**：本仓选择偏向后者。
