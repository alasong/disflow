# 0003 运行视图 v10：看板 = 阶段列，树不是一块板

- **Status**：Active
- **Date**：2026-10-11
- **Supersedes**：[0001](0001-运行视图-v8-可用性四修.md)、[0002](0002-看板-v9-默认只列运行中加待完成.md) 的运行视图部分

## Context

v8/v9 之后，运行视图仍**按树铺块**（一棵树一块 + 选树 + 批次注解区）。用户当场纠正：
「我就想看看板运行视图，按照几个看板，分别显示 running 和 pending 的任务」
+「树只是看板中条目的组织关系」。即：**看板本身就是一屏**，树是板内的组织方式，不是外层的板。

## Decision

`.agents/skills/disflow/lanes_watch.py` **整文件重写**（旧版按树铺块 + 选树 + 批次注解区**全删**）：

- **列** = 配置的 `stages`（与 `board` **同源**）→ 每列按 **running（运行事实优先于投影 status：
  有在跑 lane 就算运行中）/ pending** 分组列条目；
- 容器行作为「`◦ 需求（树目标）`」；列内按**同列祖先链**缩进；
- 行尾 `← 树名` **只在多于一棵树时**出现；
- 在跑条目就地给 `▸ lane … 已跑/静默/消息数`，`-v` 才给 `⌘ 最后命令` / `↳ 自报进展`；
- `--all` 连终态；读不到 `state.json` 或 lane 找不到节点都**明说**；`once` / 非 TTY **零控制序列**。

## Consequences

- 看板与运行视图**共享同一行序实现**（`views.board_rows` 是唯一行序来源，按 `kind` 消费）——
  **任何一侧都不许再写一套分列/缩进**：同一判据两份实现 ⇒ 两面分叉。
- 「数据源分离、布局同源」成为 §6 的契约：看板 = 纯 disflow 事实；运行视图 = disflow 事实 + pi 运行目录。
