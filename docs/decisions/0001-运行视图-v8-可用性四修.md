# 0001 运行视图 v8：可用性四修

- **Status**：Superseded by [0003](0003-运行视图-v10-按板列不按树.md)（v10 整文件重写）
- **Date**：2026-10-11

## Context

宿主侧运行视图（`.agents/skills/disflow/lanes_watch.*`）首版可用后，用户当场提了四条可用性问题：
刷新会丢回滚、终态行把长 goal 全打出来挤爆屏幕、默认把已完成也列出来（显示太多）、
没有在跑节点时整片空白（分不清「真没在跑」还是「卡住了」）。

## Decision

| 修复 | 判据 |
| --- | --- |
| **默认刷新改追加式** | 备用屏（`\033[?1049h`）**没有回滚缓冲** ⇒ 滞轮失效；默认改「每轮一整块 + 时间戳头」的追加式（保留回滚）；备用屏只能**显式** `--screen`（不闪，代价：无回滚）；**非 TTY 零控制序列**（判据：输出不含 `\033[`） |
| **终态行不打 goal** | `✓ 完成` / `— 跳过` 行只给 `标记 + id + 状态`；其余行走 `truncate_goal`（首行、≤80 字、`…`）。完整文本只在 `board --json`（`views.truncate_goal` **唯一实现**） |
| **默认只列「运行中 + 待完成」** | 只列「运行中 + 待完成（可派 / 待前置 / 被在跑挡住）」+ 结构行，隐藏 `✓/—/✗` 与非规范兜底；`--full` 恢复全部状态；`--active`/`--open` 保留为显式写法；`once` / `all` / `N` / `-v` 一个没动；次级「派发批次」区默认不显示（`-v` 才展开） |
| **无在跑节点明说** | `◈/⌘/↳` 只对在跑节点显示是设计；无在跑节点时**显式**打「当前无在跑节点 ⇒ 无实时进展」，不再一片空白 |

## Consequences

- 默认行为变得「干净」但**事实不丢** —— 隐藏的状态仍可用 `--full` / `--json` 取回。
- 由此确立一条通用判据：**默认视图可为可读性裁剪，机器态（`--json`）恒为全量事实**。
