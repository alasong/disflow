# 0005 看板提升为一等实体

- **Status**：Active
- **Date**：2026-10-11
- **Supersedes（部分）**：[0003](0003-运行视图-v10-按板列不按树.md) 的「看板 = 视图」定位本身不改，
  改的是**看板在数据模型里的地位**：0003 之后看板是「树的投影」，本次后看板是**独立的一等实体**。

## Context

早期（`docs/decisions/0002` / `0003` + 需求 FR-21/22、目标 4、术语表）把看板定为**视图**：
「同一投影的三种渲染之一，不是第二份存储」「多块板 = 多棵作用域隔离的树」。树是实体、是隔离与
权威分发者作用域；看板只是它的一屏渲染。

用户的模型不是这样（2026-10-11 当场提出）：

1. **看板应是固定的结构，哪怕里面没有东西** —— 像墙上钉的一块板子，列永远在，卡片只是往格子里放。
2. **看板相关的数据结构、分发器、验收器都是看板附属的东西** —— 规则挂在板上，不散落在每个节点上。
3. **树只是组织结构** —— 用来组织依赖关系、做分层与 DAG；它是**板内**的组织维度，不是板的外壳。
4. **分解的产物挂回看板** —— 例如「需求看板」，分解出来的子需求挂到该板的对应列上。
5. **（后续）看板做成动态的** —— 用户可以提前设定流程结构（这与 `backlog` D4「动态看板」同源，D4 已实现为逐树可选覆盖）。

归纳新判据：**看板是一等实体；树/图/视图是它的内部维度与渲染。**

## Decision

把看板从「视图」升为**一等实体**，并厘清它与树/图的关系：

| 维度 | 旧 | 新 |
| --- | --- | --- |
| 看板地位 | 视图（同一投影的渲染） | **一等实体**：稳定 `id` + 固定列结构；随事件流持久化、可重放；**空也在** |
| 列结构 | 由 `boards.json` / 树板集派生渲染 | 看板**自身**的固定结构；列恒在，不因无任务而消失 |
| 分发器 | 树级（`drive(tree)`） | **看板的附属**：分发策略由看板（逐列）持有（FR-30，未实现） |
| 验收器 | 节点级（`node.acceptance` + `entry`） | **看板的附属**：验收策略由看板（逐列）持有，节点判据由它派生（FR-31，未实现） |
| 树 | 实体、隔离单元、上下文继承 | 看板**内**的组织维度（`parent` 层级、DAG、分层、上下文继承） |
| 分解 | `expand` 写 `parent` + `stage` | 分解产物**挂回看板对应列**（同一机制，语义上属看板） |
| 看板 : 树 | 1:1 | **保持 1:1**（FR-22 不变）；改的是「谁挂谁」 |

**不改的**：看板/树/图仍**同源**（同一投影的不同渲染，`FR-21` 的一半保留）；跨板（跨树）依赖仍
降级为 `awaits` 显式完成信号（FR-23）；多板仍 = 多棵作用域隔离的树（FR-22）。总原则不变：
**单一事实源、看板不是第二份存储**（`events.jsonl` 仍是唯一真相；「一等实体」指它有身份与固定
结构、随事件流持久化，**不是**新开一份独立存储）。

## Consequences

- **需求基线变更**：`docs/requirements.md` 的 §0 定位、§2 目标 4、FR-21、§6 术语表改写；新增
  FR-30（分发器是看板附属）、FR-31（验收器是看板附属）、FR-32（动态看板：结构可预设/逐树覆盖）。
- **设计现状 vs 目标**：`docs/design.md` §6 当前仍描述**现状**（视图形态）——本次只加一条指向本
  ADR 的目标 banner；实现升级后再改写 §6。
- **机检同步**：`scripts/goal_check.py` 的 g4、`scripts/fr_check.py` 的判据表与计数随之更新；
  FR-30/31 进入 `[未实现]`（诚实列出缺口），FR-32 进入 `[测试]`（D4 已实现）。
- **待实现（不在本次）**：看板持有逐列分发策略（WIP/就绪规则）与逐列验收策略；实现前 FR-30/31
  保持 `[未实现]`。

## 后续

- **2026-10-11（同日）**：FR-30/31 **已实现**。板条目扩为可带两类策略（随 `tree.init`/`tree.boards`
  进事件流、可重放）：
  - **`wip`**（逐列并发在跑上限）由 `dispatch.drive` 消费——列满则同列其余就绪者进 `deferred`；
  - **`acceptance`**（逐列默认验收）由 `Engine._effective_acceptance` 在 `done` 派生——节点自带优先。
  空策略不写出（`dump` 只写非空）⇒ 旧事件流读数逐字节不变；`tests/test_board_policy.py` 钉住；
  `docs/design.md` §6.2 记录现状。
