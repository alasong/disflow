# 0011 web 入口：实现（只读 + 写面经 Engine；形态 A/B 的合取）

- **Status**：Active
- **Date**：2026-10-11
- **Supersedes**：[0008](0008-看板不做web化.md) 的「不做」裁决（**不推翻它的形态排序与
  结构性非目标** —— 两者原样沿用）。
- **关联**：[0005](0005-看板提升为一等实体.md)（看板是第三种渲染）、
  [0009](0009-步骤准入-软门槛.md)（brief 是「步骤调 skill」的接点）。

## Context

用户指令（2026-10-11）：「**我需要一个入口来下发任务。在 Web 上同时把资产也展示一下。**」

前置事实（均已核对源码，非推测）：

| 层 | 现状 | 对 web 的含义 |
| --- | --- | --- |
| 事实源 | `events.jsonl` 唯一真相，`state.json` 可重放 | 无需为 web 新增存储 |
| 机读契约 | `views.board_layout()` 返回结构化 dict；`board --json` 是其直接序列化 | **web 要的接口已存在** |
| 写路径 | `Engine._write` 在 `store.lock`（`flock`）内「读投影 → 校验 → append」 | 跨进程安全已保证，**web 必须复用它** |
| 资产契约 | `assets/index.jsonl`（一行一资产，含 `trust`/`stale_basis`） | 直接消费，不解析 `registry.json` |
| 只读性 | `board` 跑前后状态逐字节不变（`tests/test_cli_readonly.py` 钉住） | 只读端点安全 |

## Decision

**形态 = A + B 的合取**（ADR 0008 的形态序）：**只读端点用 HTTP 服务暴露事实；写端点只开
「下发任务」所需的动词白名单，且一律经 `Engine`。**

四条实现判据：

1. **薄壳，不是第二实现**：`disflow/web.py` 不重写任何看板布局 / 就绪判定 / 门 / 锁 ——
   `/api/board` 直接返回 `views.board_layout(...)` 的返回值（**同一份结构**，
   `tests/test_web.py` 断言 `payload == views.board_layout(...)`）。判据来源：
   `docs/design.md` §6「同一判据两份实现 ⇒ 两面分叉」。
2. **写面走唯一写点**：`POST /api/write` 的每个分支只**转发**到 `Engine` 的同名公开方法。
   读 → 校验 → 加锁 → append 全在 `Engine._write` 里，web 层零复制。
   **禁止**直接改 `state.json`（绕过锁与门）。
3. **写动词白名单**：只开 `expand` / `start` / `collect` / `done` / `fail` / `skip` / `retry`
   （= 「下发任务」所需）。**不开** `close` / `reopen` / `reap` / `rescope` / `worktree apply`
   这类不可逆或高副作用的动词 —— web 的体积在风险面上，不在动词数上。
4. **零第三方依赖**（NFR-1）：只用 `http.server` / `json` / `urllib`。
   默认只绑 `127.0.0.1`（本地工具，不是网络服务）；不做常驻 daemon / WebSocket / 前端框架
   （ADR 0008 的结构性非目标，继续遵守）。

**端点**：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/` | 单页前端（内嵌 HTML，无构建链） |
| GET | `/api/trees` | 全部树摘要（同源 `Engine.status`） |
| GET | `/api/board?tree=<t>[&by=column\|board]` | 看板（同源 `views.board_layout` / `boards_layout`） |
| GET | `/api/assets` | 资产表（读 `assets/index.jsonl`；坏行 raise，不静默跳过） |
| GET | `/api/host-next?tree=<t>` | 本轮该派谁 + 完整 brief（纯读） |
| POST | `/api/write` | 白名单写动词，body `{action, tree, ...}` |

## Consequences

**已落地并通过门**：

- `disflow/web.py`（薄壳 + 内嵌前端）；`disflow/__init__.py` 导出 `web`
  （修了「显式再导出列表」漏项导致的静态分析 unknown symbol）。
- `tests/test_web.py`：**12 项真 HTTP 测试**（起真服务、真发请求，不 mock handler）——
  覆盖三条判据：①只读端点跑一遍后 `events.jsonl`/`state.json` **逐字节不变**；
  ②写面拒收路径（未就绪 409 带阻塞者名单 / 缺 holder 400 / 未知 action 400）；
  ③载荷与 `views.board_layout` **逐字节相等**。
- `README.md` 增 web 用法；`assets/registry.json` 的 `pkg`/`tests` purpose 反映覆盖面。
- 全量门：**55 文件 / 55 通过**（web 前是 54）。

**测试抓到的真缺陷**（记录，因为「测试抓到了什么」比「测试有多少」重要）：
- `test_read_endpoints_do_not_touch_state` 初版失败 —— 测试助手对 `/` 硬编了 `json.loads`，
  而 `/` 本就返回 HTML。**是测试的 bug，不是 web 的**；改成按 `Content-Type` 分派解码。

**已知限制（诚实记录，不是待办粉饰）**：

- **无鉴权**：默认绑 `127.0.0.1` 即依赖「只在本机可达」这一事实。若将来要远程访问
  （ADR 0008 的触发条件 ①），**必须先解决鉴权**，不能只把 host 改成 `0.0.0.0`。
- **写面尚无并发压测**：跨进程安全靠 `Engine._write` 的 `flock`（既有机制、已有测试），
  但 **web 层自己的并发**（两个浏览器同时 POST）未专门测 —— 理论安全（同进程内
  `ThreadingHTTPServer` + `Engine` 的锁），无实测证据。
- **前端只有列视图**：未做依赖图/甘特（那是 ADR 0008 的触发条件 ③，未出现）。
